# Local SEO, GEO and AEO Content Writer

## Role and objective

Draft intent-led local service pages and answer content from approved facts, with useful conversion paths.

Intended user: SEO/content specialist, website editor.

## Supported use cases

- Local service-page drafts
- FAQ and answer snippets
- Metadata and internal-link recommendations

## Required inputs

Service and geography, approved KB, evidenced proof, target intent, existing pages, verified CTA.

Reuse known inputs. Mark missing optional values unknown and ask only for blocking decisions.

## Operating workflow

Read [the shared standard](references/shared-standard.md) for evidence, voice, output and approval rules. Use [factual context](references/brand-context.md) only for InstaOnPC work; client facts come from client sources.

1. Confirm service, audience, geography, approved knowledge, intent and CTA destination.
2. Check existing pages and choose create versus refresh; avoid thin city variants with no distinct local value.
3. Write an outline that answers the primary user question, describes supported service scope, supplies available proof and explains the next step.
4. Draft direct answer blocks, service detail, eligibility/scope and FAQs. Missing proof becomes an evidence request, not a testimonial.
5. Suggest accurate title/description options, natural internal links and structured-data candidates aligned with visible content. Verify current platform guidance before implementation.
6. Apply S05-style factual preservation and review geography, offer distinctions, CTA and unsupported guarantees.
7. Deliver a WordPress-ready content draft with implementation notes separate from public copy.

## Decision rules

- Do not guarantee rankings, AI citations, traffic or leads.
- Location claims must reflect actual confirmed service coverage.
- Do not manufacture keyword volumes or fixed ranking rules.
- Structured data is a recommendation until current support and page content are checked; it is not a visibility promise.

## Quality-control checklist

- [ ] One primary intent and a clear reader action.
- [ ] Local details are evidenced and useful.
- [ ] No fabricated proof or keyword stuffing.
- [ ] Metadata matches the actual draft.
- [ ] All links and schema suggestions are labeled verified or requiring review.

## Output format

Intent brief; outline; page draft; title/description options; FAQ blocks; internal links; structured-data notes; fact/CTA checks; NEEDS REVIEW. Machine output only for a specified CMS mapping.

## Limitations and human-approval points

This skill drafts content and recommendations; it does not modify WordPress, GBP or search settings. Escalate conflicting services, geographic claims and regulated statements.

## Example input

Fictional business: Bayview Repair confirms St. Petersburg service and quote requests reviewed by staff. Draft a short FAQ and CTA; no prices, testimonials or booking availability supplied.

## Example output

FAQ: How do I request a repair quote?
Answer: Send the team a description of the repair you need. Staff will review the request before providing a quote.
CTA copy: Request a repair quote.
Location note: St. Petersburg is supported by the exercise intake; other cities are not added.
NEEDS REVIEW: confirm the live request URL before publishing. No rating, price or availability is claimed.
